
# 개인용 온라인 저장과 본인 인증

Flutter → 본인 로그인 → API → Supabase PostgreSQL 구조입니다. 서버는 관리자 키 대신 로그인한 본인의 세션을 전달합니다. DB에도 접근 규칙(RLS)을 적용해 허용한 본인 계정만 거래를 읽고 수정하도록 제한합니다.

## 계정 연결 후 진행 순서

1. 개인용 Supabase 프로젝트를 준비합니다. 시험은 Free 플랜으로 시작하고 유료 전환은 별도로 확인합니다.
2. `migrations/202610130001_personal_trades.sql`을 적용합니다. 이 단계만으로는 아무 계정도 거래에 접근할 수 없습니다.
3. Auth 설정에서 신규 가입과 익명 로그인을 끕니다.
4. 본인 이메일에 대응하는 Auth 사용자를 준비합니다. 비밀번호는 본인이 설정하며 코드나 대화에 남기지 않습니다.
5. 관리자 화면에서 해당 계정의 UUID를 확인해 `private.app_owner(user_id)`에 한 건만 등록합니다. 이메일 문자열만으로 본인을 판정하지 않습니다.
6. 앱 서버에 `DB_MODE=supabase`, `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 설정합니다. 공개 가능한 publishable/anon 키만 사용합니다. secret/service_role 키는 앱과 API에 넣지 않습니다.
7. 실제 프로젝트에서 본인·미허용 계정·미로그인 접근을 시험합니다. GitHub Postgres 테스트는 규칙 검증이며 실제 프로젝트 인증 설정 검증을 대신하지 않습니다.
8. 기존 Google Sheets를 보존하고 CSV를 미리보기 후 가져옵니다. 건수·매수/매도금액·손익·메모를 대조합니다. 원본 시트를 삭제하지 않습니다.

Free 플랜은 비활성 상태에서 정지될 수 있고 백업 제공 조건도 플랜에 따라 다릅니다. 무료 사용 시에도 별도 백업을 준비합니다. 무료 웹 호스팅에는 첫 접속 시 기동 대기가 있을 수 있어 시험 후 필요한 운영 조건을 정합니다.

현재는 연결 코드를 준비한 단계입니다. 실제 온라인 DB 생성·본인 등록·데이터 이전·공개 배포는 아직 실행하지 않았습니다.
