## 1. 추가 기능

- 새 메뉴 **포지션 R·CR·E**: 최초 매수부터 전량 청산까지 별도 매매 사이클.
- 최초 매수가·최초 손절가·최초 수량으로 고정하는 1R. 차수별 독립 손절가와 잔여 수량으로 계산하는 CR. 최초 수량 대비 현재 수량인 E.
- 차수별 매수, 명시적으로 배분하는 부분/전량 매도, 손절 변경 이력, 매수 메모와 주가 관측 기록.
- 실현·미실현·총손익 R, 손절 시 예상 최종 손익, 수익 반납액·반납 R·반납률. CR에서 보호 이익을 차감하지 않습니다.
- 입력한 관측값 기준 최고 총손익, 최근 추가 매수 이후 최고 총손익, 최고 총손익 대비 현재 반납률.
- 추가 매수 시뮬레이터: 기존 차수별 손절 변경안, 추가 전후 CR/E, 보호 손익, 예상 반납, 추가 수량 절반의 비교, 누적 매수금액·평가금액·계좌 비중. 시뮬레이션은 DB에 저장하지 않습니다.
- 사용자 설정: 최대 E/CR, 보호 조건 시작 R/최소 보호 R, 초기 계좌 위험 비율, 계좌 평가액, 경고 전체 비활성화. 주문을 실행하거나 강제 금지하지 않습니다.
- **R-배수 분석**: 평균 손실금을 R로 간주하던 계산을 제거하고, 최초 R이 확정된 종료 사이클의 성과 통계로 연결했습니다. 누적/평균 R, 수익·손실 평균 R, 승률, 기대값, 피라미딩 여부 비교, 거래별 확정 R을 표시합니다.
- 전량 청산은 기존 거래 목록과 매매일지에 `RISK_<cycle id>` 한 건으로 자동 연결됩니다. 체결 금액은 변경·삭제를 막고, 매매일지의 메모·태그·심리·규율은 기존 방식으로 수정할 수 있습니다.
- 다른 화면의 변경은 30초 주기 및 앱 복귀 시 불러옵니다. 사이클 버전 검사로 오래된 화면의 저장을 거절합니다.

## 3. DB 변경 내용

2026-11-16 운영에 적용했습니다. 기존 `trades` 테이블과 인증/RLS는 그대로 유지합니다.

- `position_cycles`: `(owner_id, id)` 기준 사이클의 원본 이벤트 이력. 기존 이벤트의 변경/삭제, 최초 진입 기준의 수정은 트리거로 거절합니다. 새 이벤트 한 건씩만 추가합니다.
- `position_risk_settings`: 사용자 위험 설정. 계산된 CR/E를 별도 저장하지 않습니다.
- `commit_position_cycle`: 기존 본인 JWT로 실행하는 **security invoker** 함수. 버전 검사·이벤트 추가·최종 청산의 기존 거래 연결을 한 트랜잭션에서 처리합니다.
- 새 테이블도 기존 `is_app_owner()`와 `auth.uid()`를 함께 검사합니다. 익명 접근과 다른 계정 접근을 허용하지 않습니다. 관리자 키를 앱에 추가하지 않습니다.
- 닫힌 거래의 기존 금액 필드는 이벤트에서 생성한 읽기 전용 연결 기록입니다. R 계산의 원본은 사이클 이벤트입니다. 별도 매매일지 저장소를 만들지 않았습니다.

## 4. 계산 검증

백엔드 전체 24개 테스트 통과. 그중 9개 테스트 묶음이 신규 계산·위험 규칙·API 연결을 검증합니다.

| 필수 사례 | 결과 |
| --- | --- |
| 최초 100,000원 × 100주, 손절 90,000원 | 1R=1,000,000원, CR=1, E=1 |
| 현재가 110,000원, 최초 차수 손절 100,000원 | 미실현 +1R, CR=0, E=1 |
| 120,000원 × 100주 추가, 추가 손절 110,000원 | E=2, CR=1, 미실현 +2R, 손절 시 −1R |
| 140,000원에서 각 차수 50주씩 매도 | 실현 +3R, 미실현 +3R, 총 +6R, E=1 |
| 남은 차수 손절을 각각 매수가로 변경 | CR=0, 보호 수익 +3R |
| 130,000원에서 각 차수 50주씩 전량 매도 | 누적 확정 +5R, E=0, CR=0 |

추가로 손절가가 매수가보다 높을 때의 독립 보호 수익, +0.5E/+1E 추가, 정보 부족, 과다 매도, 중복 배분/주문, 과거 일시, 재진입 새 사이클, 비저장 시뮬레이션, CR=0에서의 반납 위험, 소수 금액·수량·수수료, 경고 비활성화를 확인했습니다.

가격·수량은 소수점 6자리까지 입력합니다. 곱셈/누적 금액은 BigInt 고정 소수점(12자리)으로 계산합니다. 통계의 R 합계·평균은 분수로 누적한 뒤 표시할 때만 숫자로 변환합니다. R 비율 표시는 소수점 2자리이며, 계산 API는 최대 9자리 비율을 반환합니다.

손익 0인 종료 거래는 전체 건수에 포함하고 승리/패배 건수에서는 제외합니다. 따라서 승률+패배율은 100%보다 작을 수 있습니다. 기대값은 전체 거래 기준 평균 R과 일치합니다. 최초 R이 없는 거래는 금액을 추정해 R 통계에 넣지 않습니다.

## 6. 남은 적용과 제한

1. **운영 적용**: 관리 연결 복구, 스키마 확인, 추가 마이그레이션 적용, 소유자 권한의 생성·청산 RPC 검증을 완료했습니다. 가상 체결 검사는 트랜잭션 전체를 롤백해 잔여 데이터가 0건입니다. 새 테이블의 익명 요청은 401로 차단됨을 확인했습니다. 보안 진단에는 새 테이블 관련 문제가 없었습니다. 기존 계정의 유출 비밀번호 차단 미사용 권고와 private.app_owner 의도적 접근 차단 INFO는 남아 있습니다. [계정 보안 권고 설명](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
2. 실시간 시세/증권사 주문 연동은 추가하지 않았습니다. 현재가는 직접 입력합니다. 최고 손익도 저장한 관측값만 추적하므로 장중 실제 최고 손익과 다를 수 있습니다.
3. 기존 청산 거래를 R 사이클로 자동 변환하지 않습니다. 최초 손절가와 체결 수량이 없어 안전하게 복원할 수 없기 때문입니다.
4. 체결은 불변 이력이며 임의 편집/삭제 UI를 제공하지 않습니다. 잘못 입력한 실제 체결을 정정하는 별도 감사 절차는 이번 범위에 추가하지 않았습니다.
5. 손절가는 계획값입니다. 갭하락·슬리피지 등 체결 차이는 실제 매도 체결을 입력할 때 실현손익에 반영됩니다. 예상 보호 손익을 보장하지 않습니다.
6. 위험 경고는 앱 안에 표시되며 푸시 알림이나 강제 주문 차단 기능이 아닙니다.

## 7. 사용 순서

1. **포지션 R·CR·E → 새 매매 사이클**에서 최초 매수가·수량·손절가를 입력합니다. 주문 ID는 자동 생성되며 재시도 시 같은 ID로 중복을 막습니다.
2. **현재가 갱신**으로 평가 기준 주가를 기록합니다. **손절가 변경**은 차수별로 수행합니다.
3. 추가 매수 전에는 아래 **위험 시뮬레이터**에서 예상 매수가·추가 수량·추가 손절가와 기존 손절 변경안을 입력합니다. 결과는 저장되지 않습니다.
4. 실제로 체결된 경우에만 **추가 매수 체결** 또는 **차수별 매도**로 기록합니다. 매도 수량을 차수별로 직접 배분합니다.
5. **위험 규칙**에서 한도와 계좌 평가액을 설정합니다. 경고 사용 스위치를 끌 수 있습니다.
6. 전량 청산 시 기존 **거래 기록 → 매매일지**에서 복기를 작성하고, **R-배수 분석**에서 종료 사이클 성과를 봅니다. 같은 종목에 다시 진입하면 새 사이클을 만듭니다.
