# 계좌 자금 자동 계산

2026-11-17 추가. 기존 Supabase `position_risk_settings.payload.accounts`에 계좌 자금을 저장합니다. 새 테이블·DB 서비스·관리 키는 추가하지 않습니다.

## 사용법

트레이딩 마스터 → 포지션 R·CR·E → 계좌별 금액 설정에서 DC 퇴직연금, ISA, 일반의 기준 자금을 원 단위로 입력하고 저장합니다.

금액 하나로 아래 값이 자동 계산됩니다.

- 1E = 기준 자금 ÷ 4 (종목 최대 투자 예산)
- 1R = 기준 자금 ÷ 80 (1E의 5%, 기준 자금의 1.25%)
- 1유닛 = 기준 자금 ÷ 16 (1E의 25%)
- 유닛 위험 = 기준 자금 ÷ 320 (1R의 25%)
- 1E = 4유닛, 최초 진입 = 1유닛, 기본 손절폭 = −5%

계좌를 선택한 뒤 새 매매 사이클을 생성합니다. 매수가를 입력하면 1유닛 예산 안에서 매수 가능한 정수 수량(내림)과 기본 손절가가 제안됩니다. 실제 체결 수량과 손절가로 수정해 저장할 수 있습니다. 1주 가격이 예산보다 높으면 0주와 안내를 표시하며 0주 체결은 저장할 수 없습니다.

## 계산·호환성

- 새 계좌 사이클의 R 분모는 해당 계좌의 고정 1R입니다. 최초 한 유닛의 실제 손절 위험을 1R로 다시 정의하지 않습니다.
- E = 잔여 물량 매입금액 ÷ 고정 1E. 주가 상승만으로 E가 늘어나지 않습니다.
- CR = 차수별 `max(0, 매수가−손절가)×잔여 수량` 합계 ÷ 고정 1R.
- 손익 R·수익 반납 R·시뮬레이션·청산 성과는 같은 고정 1R을 사용합니다.
- 계좌 자금과 계좌 ID는 최초 매수 이벤트의 `basis`에 스냅샷으로 기록됩니다. 기존 DB의 이력 불변 트리거로 보호합니다. 설정 금액을 바꿔도 기존 사이클의 R·E·유닛 기준은 유지되며 새 사이클부터 새 금액을 씁니다.
- 매수 화면을 연 뒤 다른 기기에서 자금이 변경되면 오래된 기준의 최초 저장을 409로 거절합니다.
- 계좌마다 E/CR 한도는 각각 1, 초기 위험 기준은 자금의 1.25%입니다. 한도 초과는 경고이며 체결 입력을 강제로 막지 않습니다. 수익보호 경고와 전체 경고 사용 스위치는 유지됩니다.
- 계좌별 성과를 따로 집계합니다. 전체 계좌 위험은 원화로 합산합니다. 서로 다른 계좌의 R을 더한 합계를 제공하지 않습니다.
- 전체 위험은 앱에 기록된 보유 사이클 기준입니다. 실제 증권사 잔고를 자동 조회하는 기능은 아닙니다.
- 계좌 정보가 없는 기존 거래·사이클은 임의 분류하거나 재계산하지 않습니다. 기존 미분류 사이클은 종전 최초 진입 R·수량 E 기준을 유지하며, 해당 필터에서 볼 수 있습니다. 과거 청산 거래의 계좌는 미상으로 남깁니다.
- 새로운 청산 기록은 기존 거래/매매일지에 계좌 ID·이름을 함께 연결합니다. 기존 CSV 가져오기 경로는 변경하지 않았습니다.

## 구현

- `position-risk.mjs`: 자금·유닛 계산, 계좌 설정 검증, 고정 계좌 기준 계산 및 원화 합산.
- `server.mjs`: 계좌 조회/설정, 1유닛 제안, 최초 체결 기준의 서버 측 스냅샷 생성. 사용자 요청의 임의 basis는 사용하지 않습니다.
- `capital_accounts.dart`: 금액 입력·즉시 계산, 1유닛 매수 입력 화면.
- `position_risk.dart`: 계좌 선택·포지션 필터·계좌 성과·전체 위험 표시.
- `trade.dart`, `master_journal.dart`, `master_reference.dart`: 계좌 메타데이터와 고정 R 명칭 표시.
- `position-risk-test.mjs`, `capital_accounts_test.dart`, `position_risk_test.dart`, 합성 JSON fixture: 계산·영속성·모바일 화면 검사.

사용자 계좌 금액은 본인 전용 DB에만 설정하며 앱 소스의 기본값으로 넣지 않습니다. 미설정 계좌는 금액을 입력하도록 안내합니다.
